# Finance — contrato (consumo)

Dueño: `personal-os-back/docs/modules/finance/`. Query keys: `src/modules/finance/shared/types/api.ts` (`['finance', ...]`).

| Superficie UI                                    | HTTP (prefijo `/finance`)                                                                                                                                                                                                                                                         |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Resumen                                          | `balance-sheet`, `analytics/*`, `budget-status`                                                                                                                                                                                                                                   |
| Movimientos                                      | `transactions`, `transfers` (POST y PATCH `:id`), confirm/reverse, `transactions/:id/link` (POST y DELETE)                                                                                                                                                                        |
| Planificación                                    | ahorros (`savings-goals`, `:id/contributions` con `accountId`, DELETE del aporte), préstamos (+ `/loans/:id`, `/loans/:id/installments`, `POST /loans/:id/pay-next-installment`), cobros, `budgets` (paginado; listado en `/finance/planning`, detalle en `/finance/budgets/:id`) |
| Comercios y suscripciones                        | `merchants` (+ `:id`, `:id/merge`, `:id/logo`, `suggest`), `recurring` (+ `:id`, `upcoming?days`)                                                                                                                                                                                 |
| Cuentas                                          | institutions (+ `:id/logo`), accounts, cards (+ `:id/balances`, `:id/credit-limit`, `:id/statements`, PATCH del corte para registrarlo a mano), categories                                                                                                                        |
| Papelera de reciclaje (`/finance/recycle-bin`)   | `recycle-bin` (inactivos de instituciones/cuentas/tarjetas/préstamos y borrados pendientes del diario). Archivar es `PATCH isActive:false` y desarchivar `PATCH isActive:true`; un borrado vuelve con `POST <entidad>/:id/restore`                                                |
| Correos                                          | `email-sync/mailboxes`, `email-sync/sources` (POST vínculo con `bankSenderEmail`), pending/assign/retry, `email-sync/oauth/google/*`                                                                                                                                              |
| Tipos de moneda (`/settings/finance/currencies`) | `exchange-rates?base&quotes` (tasas de hoy UTC, `rate: null` si falta), `base-currency` (POST con rebase)                                                                                                                                                                         |

Mutaciones de cuentas/tarjetas/loans/instituciones/txs confirmadas/email assign invalidan `FINANCE_BALANCE_SHEET_QUERY_KEY`.

Listas cursor-paginadas `{items, nextCursor, hasMore}` (hook `useInfiniteFinanceList` + `InfiniteListSentinel`, carga al hacer scroll): `transactions`, `budgets`, `budgets/:id/transactions`, `cards/:id/statements`, `accounts/:id/history`, `cards/:id/history`, `loans/:id/installments`, `receivables/:id/payments`, `savings-goals/:id/allocations`, `email-sync/pending`, `email-sync/messages`, `merchants`, `recurring` y los eliminados de `recycle-bin` (`{ archived, items, nextCursor, hasMore }`). El resto de listas sigue devolviendo arrays.

Cada `DELETE` de una entidad devuelve `undoId` y guarda un snapshot en `fin_deletion_journal`; `POST /finance/<entidad>/:id/restore` deshace el borrado y repone filas, enlaces y saldos. El toast de la app ofrece "Deshacer" durante unos segundos.

Presupuestos: el listado vive en `/finance/planning` (REV-WEB-012); el detalle sí tiene ruta. Cuentas y cobros se reciclan con archivar / `CANCELLED`; no hay DELETE.
